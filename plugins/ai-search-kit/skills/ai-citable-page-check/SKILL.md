# AI-Citable Page Check — ตรวจก่อนเผยแพร่

> 📍 ในคลาส: **Workshop 4 ขั้นที่ 3 · ตรวจก่อนเผยแพร่ (ai-citable-page-check)** · ขั้นต่อไป: เผยแพร่ → Request Indexing → แผน 30 วัน (Module 6) · วัดซ้ำใน Mention Lab แล้ว `/ai-visibility-check`
> ตอบทุกครั้งให้ขึ้นบรรทัดแรกด้วย `📍 Workshop 4 ขั้นที่ 3 · ตรวจก่อนเผยแพร่ (ai-citable-page-check)` และเมื่อแนะนำขั้นต่อไป ให้เรียงตามลำดับ Workshop ในคลาส (1 prompt-finder → 2 ai-visibility-check → 3 site-readiness-audit → 4 brand-brain → ai-content-writer → ai-citable-page-check)

ตรวจ 2 เรื่องในครั้งเดียว: **AI หยิบไปตอบได้ไหม** (โครง คำตอบ หลักฐาน) และ **ข้อมูลถูกต้องไหม** (ตรงกับ Brand Brain / แหล่งทางการ)
ใช้ `references/checklist.md`

## 0. อัปเดต Brand Brain ก่อน (ถ้ามีข้อมูลใหม่กว่า)
ถ้าผู้ใช้ให้ข้อมูลทางการหรือข้อมูลที่ทีมยืนยันแล้ว ซึ่งใหม่กว่าหรือขัดกับ Brand Brain (ราคา โปร สเปก เงื่อนไข) — **อัปเดตบรรทัดนั้นใน Brand Brain ก่อน แล้วค่อยตรวจ (ตรวจกับค่าที่อัปเดตแล้ว)**:
- ใส่ป้าย `[ทางการ/ทีมให้]` + **ใครยืนยัน** (ชื่อ/ทีม/เอกสาร) + **วันที่** · ค่าเก่าย้ายไปหัวข้อ 12 "ข้อมูลที่ขัดกัน" ถ้ายังมีที่อื่นใช้อยู่
- ถามสถานะ เผยแพร่ได้ / ภายใน ถ้ายังไม่รู้ (ภายใน → ไฟล์ `brand-brain-<แบรนด์>-internal.md` ไม่ใช้ในงานที่เผยแพร่)
- ผู้ใช้บอกแค่ "ยืนยันแล้ว" แต่ไม่บอกใคร/เมื่อไร → ถาม 1 ครั้ง ถ้าไม่ได้คำตอบให้ติด `[ต้องยืนยัน]`
- ใน Cowork/Claude Code แก้ไฟล์ในโฟลเดอร์โปรเจกต์ · แชตธรรมดา ส่งบรรทัดที่แก้ให้ผู้ใช้วางทับ

## 1. รับของ
- ร่าง content (วาง/แนบ) **หรือ** URL หน้าที่เผยแพร่แล้ว (เปิดด้วยเครื่องมือเปิดเว็บ ถ้าเปิดไม่ได้ให้ผู้ใช้วางเนื้อหา)
- prompt เป้าหมายของหน้า (ถ้าไม่มี ให้เดาจากเนื้อหาแล้วถามยืนยัน 1 ครั้ง)
- Brand Brain (สำหรับตรวจข้อเท็จจริง) — ถ้าไม่มี ข้อ "ความถูกต้อง" จะตรวจได้แค่ความสอดคล้องภายในหน้า และต้องบอกผู้ใช้

## 2. ตรวจ
ไล่ checklist ทีละข้อ ให้ผล **ผ่าน / ควรปรับ / ไม่ผ่าน** พร้อมหลักฐาน (ยกประโยค/ตำแหน่งในหน้า)
- ข้อเท็จจริงทุกตัว (ตัวเลข ราคา สเปก ส่วนผสม คำกล่าวอ้าง) เทียบกับ Brand Brain: ตรง / ไม่ตรง / ไม่มีในแหล่ง · ข้อมูลที่ Brand Brain ป้าย `ภายใน` แต่โผล่ในหน้า = ไม่ผ่าน (ข้อมูลภายในหลุด)
- **ตัวเลขในหน้าต้องคำนวณลงตัว** (อยู่ในข้อ 10): ราคา − ส่วนลด = ราคาสุทธิ · ผ่อน × งวด ≈ ยอดรวม · เปอร์เซ็นต์รวมกัน · หน่วยตรงกันทั้งหน้า · ตัวเลขเดียวกันที่เขียนหลายจุดต้องเท่ากัน — คิดให้ดูทุกคู่ที่เจอ เช่น "709,900 − 120,000 = 589,900 แต่หน้าเขียน 599,900 → ไม่ผ่าน" แล้วบอกว่าตัวไหนน่าจะผิด และให้ยืนยันกับแหล่งทางการ ห้ามเดาว่าตัวไหนถูก
- ถ้าเป็น URL: เช็กด้วยว่าเนื้อหาหลักอยู่ใน HTML ที่โหลดมา (ไม่ใช่รอ JavaScript หรืออยู่ในรูป) — ถ้าสงสัยให้ส่งต่อ `site-readiness-audit`

## 3. ส่งผล
1. **คะแนนสรุป:** ผ่านกี่ข้อจาก 14 · ข้อที่ไม่ผ่านที่สำคัญที่สุด 3 ข้อ
2. **ตาราง checklist** (ข้อ · ผล · หลักฐาน · วิธีแก้)
3. **เขียนใหม่ให้เลย** สำหรับข้อที่ไม่ผ่านซึ่งแก้ด้วยข้อความได้ (คำตอบต้นหน้า, หัวข้อ, FAQ, ประโยคที่ใช้ "มัน/เขา" แทนชื่อแบรนด์)
4. **ข้อเท็จจริงที่ต้องแก้/ยืนยัน** ก่อนเผยแพร่ (ห้ามเผยแพร่ถ้าข้อมูลผิดยังอยู่)
5. หลังเผยแพร่: Google Search Console → URL Inspection → **REQUEST INDEXING** (ขอให้ Google มาเก็บหน้าใหม่) · กระจายนอกเว็บ · วัด prompt เดิมซ้ำหลัง 1–2 สัปดาห์ (Mention Lab วัดอัตโนมัติ จ./พฤ.) และดูแนวโน้ม ≥4 สัปดาห์ · ปิดท้ายด้วยคำสั่งถัดไปในกรอบ code เช่น ยังไม่ผ่าน → `/ai-content-writer ต่อยอดร่าง <ชื่อไฟล์ร่าง>.md แก้ตามผลตรวจข้อ <เลขข้อ> ใช้ brand-brain-<แบรนด์>.md` · ผ่านแล้ว → หลังวัดรอบถัดไป `/ai-visibility-check อ่านผลไฟล์ CSV รอบใหม่จาก Mention Lab แบรนด์ <แบรนด์> เทียบกับ visibility-<แบรนด์>.md`

## กติกา
- checklist นี้คือ "content ที่ดีต่อคน + ดึงคำตอบง่าย" ไม่ใช่สูตรรับประกันว่า AI จะอ้าง — พูดแบบนี้กับผู้ใช้
- ไม่แนะนำ schema หรือ llms.txt เป็นทางลัด (Google ระบุว่าไม่ต้องมี schema พิเศษสำหรับ AI features) — FAQ schema ใส่ได้เมื่อ FAQ แสดงบนหน้าจริงและตรงกัน
- หน้าเทียบคู่แข่ง: แยกข้อเท็จจริง / ความเห็น ให้ชัด ข้อมูลคู่แข่งต้องมีแหล่งและวันที่
- สุขภาพ / อาหาร-เครื่องดื่ม / การเงิน: คำกล่าวอ้างที่ไม่อยู่ในเอกสารทางการ = ไม่ผ่านเสมอ
- อ้างอิงแนวคิด: *AI SEO For Dummies* (Nathan Gotch, Wiley 2026) บทที่ 3, 4, 9, 11, 12, 14, 15, 21, 23 + Google Search Central (AI features, helpful content, scaled content abuse) — สรุปด้วยคำของเรา ไม่คัดลอกข้อความจากหนังสือ
